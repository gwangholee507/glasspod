지침서와 다르게 하거나 새로 정한 것:

- 느려짐의 기대값을 `duration_p50_ms`에서 `duration_p99_ms`로 고침. 주문 접수(`POST`)는 큐에 넣기만 해 바로 답하므로 요청 반이 빨라 p50은 거의 그대로임(첫 확인에서 p50 0.957ms)
- 느려짐의 exception event `data`는 `route`와 `job` 둘 다가 아니라 먼저 난 쪽 하나로 고침. 라우트와 작업자의 `TimeoutError`는 같은 이벤트라 SDK가 묶음(T06)
- `distinct=100`이면 SDK의 서로 다른 이벤트 상한(100)에도 닿아 SDK 경고 `more than 100 different events are being grouped`가 나온다는 것을 결정 16에 더함
- 1분 한도에 닿아 있을 때 종료하면 마지막 `draining` state event가 서버에 가지 않는다는 것을 '쓰는 법'에 적음(SDK가 묶음에서 세다가 `stop()`에서 버림, T06 결정 11). 완료 기준의 `draining` 확인은 한도에 여유가 있는 새 인스턴스로 함
- 확인 스크립트 첫 실행에서 가짜 서버가 heartbeat를 보내지 않아 SDK가 45초 뒤 다시 붙었고(T08대로), 스크립트가 첫 연결만 봐서 3개 항목이 실패함. 가짜 서버가 heartbeat를 보내게 고침. 메모리 증가를 끈 뒤 확인은 끄기 직전 metrics(최대 1초 묵음)를 기준으로 잡아 실패했고, 끈 뒤 1.5초 지난 값을 기준으로 고침. 데모 앱 코드는 고치지 않음
