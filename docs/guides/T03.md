# T03 서버 뼈대

- 우선순위: P0 · 단계 3 · 선행 작업: T02
- 브랜치: `feat/t03-server-skeleton`
- 작성: 2026-11-08

## 목표

Glasspod 서버를 실제로 띄웁니다. HTTP `/health`와 SDK용 WebSocket `/agent`를 한 포트에서 받고, 연결의 첫 메시지로 `hello`를 받아 `welcome` 또는 `reject`로 답합니다(design.md 7.1, 7.3). T04(SDK 연결)가 붙을 상대가 됩니다.

## 결정 사항

1~5는 2026-11-08에 사용자가 추천안으로 정했습니다. 6~10은 이 작업의 기본값으로 정해 미리 알렸습니다.

| # | 항목 | 결정 | 이유 |
| --- | --- | --- | --- |
| 1 | 설정값 | 환경변수로 받고, 없으면 design.md의 값을 기본값으로 씀. 정수가 아니거나 범위를 벗어나면 시작하지 않음(exit 1) | 로컬에서 바로 실행되고, 잘못된 값은 시작할 때 바로 드러남 |
| 2 | 로그 | `console` 한 줄. 시각, 수준, 내용, `key=value` 필드 | 의존성이 없음. `log.ts` 하나로 감싸 두어 나중에 JSON 로그로 바꾸기 쉬움 |
| 3 | hello 뒤 잘못된 메시지 | 경고 로그만 남기고 무시. 연결은 유지 | SDK 버그 하나로 그 Pod의 다른 데이터까지 잃지 않게 함 |
| 4 | 테스트 | hello 판단 함수(`decideHello`)만 단위 테스트. 실제 연결은 완료 기준에서 확인 스크립트로 한 번 확인 | CLAUDE.md의 '핵심 로직만' 원칙 |
| 5 | 하위 의존성의 공개 2주 규칙 | 직접 고르는 패키지에만 적용. 하위 의존성은 설치할 때 공개일과 `npm audit`을 확인해 기록 | Express가 끌어온 qs 6.17.1, encodeurl 2.0.1이 공개 11일이었음. qs는 2026-10-27에 여러 버전이 함께 수정되어, 2주 지난 버전으로 고정하면 그 수정이 빠짐 |
| 6 | 거절 규칙 | 첫 메시지가 올바른 hello가 아니면 `invalid-hello`, `protocol`이 1이 아니면 `unsupported-protocol`, 10초 안에 hello가 없으면 `hello-timeout` | `unknown-pod`는 쿠버네티스 조회가 필요해 T25에서 함 |
| 7 | 메시지 크기 | 메시지 하나는 최대 1MiB | ws 기본값(100MiB)은 너무 큼 |
| 8 | 바이너리 프레임 | 잘못된 메시지로 처리 | 메시지는 텍스트 프레임에 JSON 하나(design.md 7.2) |
| 9 | `/health` | `200 {"status":"ok"}` | 쿠버네티스 probe와 개발 확인용 |
| 10 | 종료 | SIGTERM, SIGINT를 받으면 SDK 연결을 1001로 닫고 종료. 5초 안에 끝나지 않으면 강제로 끝냄(exit 1) | 쿠버네티스는 Pod를 내릴 때 SIGTERM을 보냄 |

## 범위

### 포함

- 설정(`config.ts`), 로그(`log.ts`), HTTP(`app.ts`), WebSocket 연결 처리(`agent.ts`), 시작과 종료(`index.ts`)
- hello 판단 함수 `decideHello`와 단위 테스트
- `npm run dev:server`가 실제 서버를 띄움

### 제외

- metrics·event 보관과 상태 판단 (T11, T13). 지금은 받은 메시지의 종류만 로그로 남김
- 같은 Pod가 두 번 연결했을 때의 처리, Pod별 연결 목록 (T11)
- snapshot 요청 보내기 (T09)
- `unknown-pod` 거절과 접속 IP 대조 (T25)
- 웹 화면용 API (T14), 웹 화면 파일 제공 (T20)
- Dockerfile, 매니페스트 (T16)

## 만들 파일

```text
apps/server/src/
├─ config.ts            # 환경변수 읽기와 검사
├─ log.ts               # 한 줄 로그
├─ handshake.ts         # decideHello: 첫 메시지를 보고 welcome 또는 reject를 정함
├─ handshake.test.ts
├─ agent.ts             # WebSocket /agent: 연결마다 hello 대기, 응답, 이후 메시지 검증
├─ app.ts               # Express: /health
└─ index.ts             # 서버 시작, 종료 신호 처리
```

## 환경변수

| 이름 | 기본값 | 범위 | 쓰임 |
| --- | --- | --- | --- |
| `GLASSPOD_PORT` | 8080 | 1~65535 | HTTP와 WebSocket을 받는 포트 |
| `GLASSPOD_METRICS_INTERVAL_MS` | 5000 | 1 이상 | `welcome`의 `metricsIntervalMs` |
| `GLASSPOD_MAX_EVENTS_PER_MINUTE` | 120 | 0 이상 | `welcome`의 `maxEventsPerMinute` |

빈 문자열은 값이 없는 것으로 봅니다. 범위는 프로토콜 스키마(welcome)와 같습니다.

## 연결 규칙

| 상황 | 서버의 동작 | 종료 코드 |
| --- | --- | --- |
| 올바른 hello(protocol 1) | `welcome`을 보내고 연결 유지 | |
| 첫 메시지가 JSON이 아니거나, hello가 아니거나, 스키마에 맞지 않음 | `reject`(`invalid-hello`) 뒤 닫음 | 1008 |
| hello의 `protocol`이 1이 아님 | `reject`(`unsupported-protocol`) 뒤 닫음. v1 스키마 검사보다 먼저 봄(다른 버전의 hello는 모양이 다를 수 있음) | 1008 |
| 연결 뒤 10초 동안 hello 없음 | `reject`(`hello-timeout`) 뒤 닫음 | 1008 |
| 첫 프레임이 바이너리 | `reject`(`invalid-hello`) 뒤 닫음 | 1008 |
| hello 뒤의 잘못된 메시지, 두 번째 hello, 바이너리 프레임 | 경고 로그만 남기고 무시 | |
| hello 뒤의 올바른 metrics, event, response | 종류와 `seq`를 로그로 남김 | |
| 메시지가 1MiB를 넘음 | ws가 연결을 닫음 | 1009 |
| `/agent`가 아닌 경로로 업그레이드 | ws가 400으로 거절 | |
| 서버 종료(SIGTERM, SIGINT) | 열린 연결을 모두 닫음 | 1001 |

`reject`에는 `reason`만 담고, 자세한 이유(`detail`)는 서버 로그에만 남깁니다. reason 값은 지금 서버만 쓰므로 `handshake.ts`의 `RejectReason`에 둡니다. SDK가 reason에 따라 다르게 동작해야 하면(T04) `@glasspod/protocol`로 옮깁니다.

## 로그 형식

```text
2026-11-08T11:53:42.770Z INFO  server listening port=18080 agentPath=/agent protocol=1 metricsIntervalMs=3000 maxEventsPerMinute=60
2026-11-08T11:53:42.820Z INFO  hello accepted remote=::1 pod=shop/orders-7d9f8-x2kq1 instance=4f1c2a9e sdk=node@0.1.0 protocol=1
2026-11-08T11:53:43.090Z WARN  message ignored remote=::1 pod=shop/orders-7d9f8-x2kq1 instance=4f1c2a9e detail="message is not valid JSON"
2026-11-08T11:53:43.406Z WARN  hello rejected remote=::1 reason=unsupported-protocol detail="protocol 2 is not supported (server speaks 1)"
```

`info`는 표준 출력, `warn`과 `error`는 표준 오류로 씁니다. `remote`(접속 IP)는 T25에서 Pod IP와 대조할 때 씁니다.

## 도구 버전

직접 고른 패키지는 공개된 지 2주가 지난 버전으로, 정확한 버전으로 고정합니다.

| 도구 | 버전 | 위치 | 메모 |
| --- | --- | --- | --- |
| `express` | 5.3.0 | `@glasspod/server` dependencies | 2026-10-09 공개 |
| `ws` | 8.22.0 | `@glasspod/server` dependencies | 2026-09-26 공개. 8.22.1은 공개 8일이라 쓰지 않음. 선택 peer(`bufferutil`, `utf-8-validate`)는 설치하지 않음 |
| `@types/express` | 5.0.6 | 루트 devDependencies | 2025-12-01 공개 |
| `@types/ws` | 8.18.2 | 루트 devDependencies | 2026-09-29 공개 |

하위 의존성 76개가 새로 들어왔습니다. 2주가 안 된 것은 `qs` 6.17.1과 `encodeurl` 2.0.1(둘 다 2026-10-28 공개)이고, 결정 5에 따라 그대로 둡니다. `npm audit` 결과는 취약점 0입니다. 지금 서버 코드는 qs를 쓰지 않습니다(Express 5의 기본 query parser는 `simple`).

## 완료 기준

실제 연결은 저장소에 넣지 않는 확인 스크립트로 확인했습니다. 스크립트는 서버를 직접 띄우고 Node 22 내장 `WebSocket`으로 붙습니다.

| 확인 | 기대 결과 |
| --- | --- |
| `npm run typecheck` | exit 0 |
| `npm test` | 모든 테스트 통과. `decideHello` 7개 포함 |
| `npm run format:check` | `All matched files use Prettier code style!` |
| `npm run dev:server` | `server listening port=8080 ... metricsIntervalMs=5000 maxEventsPerMinute=120` |
| `GET /health` | `200 {"status":"ok"}`, `X-Powered-By` 헤더 없음 |
| 환경변수를 바꿔 실행한 뒤 올바른 hello | 바꾼 값이 든 `welcome` |
| hello 뒤 잘못된 메시지 4종(JSON 아님, 스키마 위반, 두 번째 hello, 바이너리) | 응답 없이 연결 유지, 경고 로그 |
| 표 '연결 규칙'의 거절 사례(첫 메시지가 metrics, JSON 아님, protocol 2, 바이너리, 10초 동안 hello 없음) | 맞는 reason의 `reject`와 1008 |
| 1MiB를 넘는 메시지 | 1009로 닫힘 |
| 다른 경로로 업그레이드 | 연결 실패 |
| SIGTERM | 열린 연결이 1001로 닫히고 exit 0 |
| `GLASSPOD_PORT=abc` | `invalid configuration` 로그와 exit 1 |

직접 해 볼 때는 서버를 띄운 뒤 다른 터미널에서 실행합니다.

```bash
npm run dev:server
```

```bash
curl -s localhost:8080/health
```

```bash
node -e 'const ws = new WebSocket("ws://localhost:8080/agent"); ws.onopen = () => ws.send(JSON.stringify({ type: "hello", seq: 0, ts: Date.now(), protocol: 1, sdk: { lang: "node", version: "0.1.0" }, pod: { namespace: "shop", name: "orders-1" }, instanceId: "i-1" })); ws.onmessage = (e) => { console.log(e.data); ws.close(); };'
```

마지막 명령은 `{"type":"welcome","metricsIntervalMs":5000,"maxEventsPerMinute":120}`를 출력합니다.
