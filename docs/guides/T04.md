# T04 SDK 연결

- 우선순위: P0 · 단계 4 · 선행 작업: T03
- 브랜치: `feat/t04-sdk-connection`
- 작성: 2026-11-09

## 목표

Node.js SDK(`@glasspod/sdk`)가 앱 안에서 Glasspod 서버(T03)에 WebSocket으로 붙습니다. 환경변수에서 서버 주소와 Pod 정보를 읽고, `hello`를 보내 `welcome`을 받습니다. 연결이 끊기면 정해진 간격으로 다시 붙습니다(design.md 7.1, 7.4, 8장). T05(metrics), T06(event)은 이 연결 위에서 메시지를 보냅니다.

## 결정 사항

1~4는 2026-11-09에 사용자가 정했습니다. 5~12는 이 작업의 기본값입니다.

| # | 항목 | 결정 | 이유 |
| --- | --- | --- | --- |
| 1 | WebSocket 클라이언트 | Node 내장 `WebSocket`. SDK에 의존성을 더하지 않음 | 사용자 결정. `ws` 8.22.0(소켓을 unref할 수 있음)과 비교함. 제약은 아래 '내장 WebSocket의 제약' |
| 2 | 환경변수가 없거나 잘못됨 | `GLASSPOD_SERVER`, `POD_NAME`, `POD_NAMESPACE` 가운데 하나라도 없거나 서버 주소가 `ws://`·`wss://`가 아니면 SDK를 끄고 경고 한 줄. 앱은 그대로 동작 | 설정 실수가 바로 드러남. 대체값(hostname, `default`)은 실수를 숨김 |
| 3 | SDK 로그 | 중요한 것만 표준 오류에 `[glasspod] ...` 한 줄: SDK 꺼짐, reject 받음, 연결 실패·끊김, 복구. 자세한 내용은 `NODE_DEBUG=glasspod`일 때만(`util.debuglog`) | SDK는 앱과 출력을 함께 씀. 서버가 오래 꺼져 있어도 앱 로그가 지저분해지지 않음 |
| 4 | 앱 이름·버전 | `glasspod.start({ app: { name, version } })` 옵션. 주지 않으면 hello에서 `app`을 뺌 | 앱 코드에서 명시적으로 정함 |
| 5 | 공개 API | design.md 8장 모양: `glasspod.start(options?)`, `glasspod.stop()`. 이미 시작했으면 `start()`는 무시. `stop()` 뒤 다시 `start()`할 수 있음 | design.md 8장 |
| 6 | 재연결 간격 | 연속 n번째 실패 뒤 대기 = min(1초 × 2^(n−1), 30초) + 0~1초 무작위. welcome을 받으면 n을 0으로 | design.md 7.4. 무작위 지연을 고정 1초로 두어 서버가 재시작된 직후 첫 재시도부터 흩어지게 함 |
| 7 | 제한 시간 | 연결 시도 뒤 10초 안에 열리지 않거나, hello를 보낸 뒤 10초 안에 welcome이 없으면 끊고 재연결 | 서버의 hello 대기(10초)와 같음. 내장 WebSocket에는 연결 제한 시간 옵션이 없음 |
| 8 | reject | 이유를 경고로 남기고, 다른 끊김과 같이 재연결 간격대로 다시 시도. 이유별로 다르게 하지 않음 | 서버를 고치거나 올리면(롤링 업데이트) 스스로 붙음. 간격이 30초까지 늘어나 부담이 작음. 그래서 `RejectReason`은 서버(`handshake.ts`)에 그대로 둠(T03에서 미뤄 둔 결정) |
| 9 | `instanceId`, `seq` | `instanceId`는 프로세스에서 처음 `start()`할 때 `crypto.randomUUID()`로 한 번 만듦. `seq`는 프로세스에서 0부터 하나씩 늘고, 재연결하거나 `stop()` 뒤 다시 `start()`해도 이어짐. hello도 하나 씀 | design.md 7.2, 7.3, 7.4 |
| 10 | 타이머 | SDK의 타이머(재연결 대기, 제한 시간)는 모두 `unref()` | 연결이 끊긴 동안에는 SDK가 앱 종료를 막지 않음 |
| 11 | 앱 보호 | `start()`, `stop()`과 모든 WebSocket 이벤트 처리를 `try/catch`로 감쌈. 전역 `WebSocket`이 없는 Node에서는 SDK를 끄고 경고 | SDK 원칙(SDK 내부 오류를 앱으로 던지지 않음). EventTarget 리스너에서 난 예외는 처리되지 않은 예외가 되어 앱을 죽임 |
| 12 | `capabilities`, `request` | 이번에는 `capabilities`를 보내지 않고, 받은 `request`는 무시(디버그 로그) | snapshot은 T09 |

### 내장 WebSocket의 제약

Node 22.22.0(undici 6.23.0)에서 2026-11-09에 확인했습니다.

- **연결이 열려 있는 동안 앱이 스스로 끝나지 않습니다.** 내장 WebSocket에는 소켓을 `unref()`할 공개 API가 없습니다. 할 일을 마치고 이벤트 루프가 비기를 기다려 끝나는 앱(예: SIGTERM에서 HTTP 서버만 닫는 앱)은 SDK 연결 때문에 남고, 쿠버네티스에서는 유예 시간(기본 30초) 뒤 SIGKILL로 끝납니다. 그런 앱은 종료 처리에서 `glasspod.stop()`을 부릅니다. SIGTERM을 처리하지 않는 앱(Node 기본 동작으로 바로 종료)과 `process.exit()`를 부르는 앱은 영향이 없습니다. SDK 원칙 '앱의 종료 동작을 바꾸지 않음'의 예외로 design.md 5.1과 개발 지침서에 적습니다.
- **첫 연결이 실패하면 `close` 이벤트가 오지 않습니다.** 연결 거부나 101이 아닌 응답(예: 404)에서는 `error`만 오고 `readyState`가 0(CONNECTING)에 머뭅니다. 연결 중에 `close()`를 불러도 `error`만 두 번 옵니다. 그래서 SDK는 `error`를 받으면 그 연결을 끝난 것으로 보고, 한 연결의 끝은 한 번만 처리합니다.
- **`http://` 주소도 받아들입니다.** 내장 WebSocket은 `http://`를 `ws://`로 바꿔 연결하지만, SDK는 설정에서 `ws://`·`wss://`만 받습니다(결정 2). `#`가 든 주소는 생성자가 예외를 던지므로 설정에서 미리 거릅니다.
- **ping이 없습니다.** 상대가 소리 없이 사라진 연결(반쯤 열린 연결)은 운영체제가 끊을 때까지 모릅니다. T08(끊김 처리)에서 다시 봅니다.

## 범위

### 포함

- 환경변수 읽기(`config.ts`)와 단위 테스트
- 재연결 간격 계산(`backoff.ts`)과 단위 테스트
- 연결 관리(`connection.ts`): 연결, hello, welcome·reject 처리, 제한 시간, 재연결, 닫기
- SDK 로그(`log.ts`), 공개 API(`index.ts`: `glasspod.start`, `glasspod.stop`)

### 제외

- metrics 수집과 주기 전송 (T05). welcome의 `metricsIntervalMs`는 받아 두기만 함
- event와 처리되지 않은 예외 (T06). `maxEventsPerMinute`도 받아 두기만 함
- 끊긴 동안의 데이터 보관과 재전송, 응답 없는 연결 감지 (T08)
- `request` 처리와 `capabilities` (T09)
- 데모 앱 (T10). 실제 연결은 저장소에 넣지 않는 확인 스크립트로 확인함
- 빌드 결과물 배포, npm 공개

## 만들 파일

```text
packages/sdk-node/src/
├─ index.ts             # 공개 API: glasspod.start(), glasspod.stop()
├─ config.ts            # 환경변수 읽기와 검사
├─ config.test.ts
├─ backoff.ts           # 재연결 간격 계산
├─ backoff.test.ts
├─ connection.ts        # WebSocket 연결, hello·welcome, 제한 시간, 재연결
├─ log.ts               # [glasspod] 한 줄 경고, NODE_DEBUG=glasspod 자세한 로그
└─ version.ts           # SDK 버전(hello의 sdk.version). package.json과 같게 둠
```

`index.test.ts`(워크스페이스 설정 확인)는 그대로 둡니다.

## 환경변수

| 이름 | 필수 | 예 | 쓰임 |
| --- | --- | --- | --- |
| `GLASSPOD_SERVER` | 예 | `ws://localhost:8080/agent` | 서버 주소. `ws://` 또는 `wss://`, `#` 없음 |
| `POD_NAME` | 예 | `orders-7d9f8-x2kq1` | hello의 `pod.name`. 쿠버네티스에서는 Downward API로 넣음(design.md 8장) |
| `POD_NAMESPACE` | 예 | `shop` | hello의 `pod.namespace` |
| `NODE_DEBUG` | 아니오 | `glasspod` | SDK의 자세한 로그를 켬(Node 표준 방식) |

앞뒤 공백은 지우고, 빈 값은 없는 것으로 봅니다. 문제가 여러 개면 경고 한 줄에 모두 적습니다.

## 쓰는 법

```ts
import { glasspod } from "@glasspod/sdk";

glasspod.start({ app: { name: "orders", version: "1.4.2" } }); // app은 선택

// 이벤트 루프가 비기를 기다려 끝나는 앱은 종료 처리에서 연결도 닫습니다.
process.on("SIGTERM", () => {
  server.close();
  glasspod.stop();
});
```

## 연결 규칙

장애는 연결이 안 되거나 끊긴 때부터 다음 welcome까지입니다. 경고는 장애 하나에 한 번만 남기고, 재시도마다의 실패와 대기 시간은 `NODE_DEBUG=glasspod`일 때만 나옵니다.

| 상황 | SDK의 동작 | 경고(표준 오류) |
| --- | --- | --- |
| 환경변수 문제, 전역 `WebSocket` 없음 | 연결하지 않음 | `disabled: ...` |
| 연결, hello, welcome | 받은 주기·한도를 저장하고 실패 횟수를 0으로 | 처음 연결이면 없음. 장애 뒤 복구면 `connected to ...` |
| 연결 실패(거부, 404 등), 10초 안에 열리지 않음 | 재연결 간격대로 다시 시도 | 장애 동안 처음 한 번 `cannot connect to ...` |
| hello 뒤 10초 동안 welcome 없음 | 끊고 재연결 | 위와 같음 |
| welcome 뒤 끊김(서버 종료 1001, 1006 등) | 재연결 | `connection lost (...)` |
| reject | 서버가 닫으면 재연결 간격대로 다시 시도 | 장애 동안 이유마다 한 번 `rejected by server: reason=...` |
| welcome 전의 다른 메시지, 검증에 실패한 메시지, 바이너리 | 무시 | 없음(디버그 로그) |
| welcome 뒤의 `request` | 무시 (T09) | 없음(디버그 로그) |
| `stop()` | 1000으로 닫고 재연결하지 않음 | 없음 |

## 로그 형식

```text
[glasspod] disabled: GLASSPOD_SERVER is not set, POD_NAME is not set
[glasspod] cannot connect to ws://localhost:8080/agent (Received network error or non-101 status code.); retrying in the background
[glasspod] connection lost (code 1001, server shutting down); reconnecting
[glasspod] rejected by server: reason=unsupported-protocol; retrying
[glasspod] connected to ws://localhost:8080/agent
```

주소는 `origin`과 경로만 씁니다(사용자 정보와 query는 뺌). `NODE_DEBUG=glasspod`이면 다음처럼 자세한 로그가 더 나옵니다(`GLASSPOD` 뒤는 프로세스 id).

```text
GLASSPOD 57390: connecting to ws://localhost:18080/agent
GLASSPOD 57390: connect failed (Received network error or non-101 status code.); retry 1 in 1306ms
GLASSPOD 57390: hello sent seq=0 pod=shop/orders-1 instance=1ef8d382-e688-4ffc-a162-f5c63d3eb1e8
GLASSPOD 57390: welcome metricsIntervalMs=5000 maxEventsPerMinute=120
GLASSPOD 57390: disconnected (code 1001, server shutting down); retry 1 in 1015ms
```

## 도구 버전

새로 설치하는 패키지가 없습니다. WebSocket은 Node 22.22.0에 들어 있는 undici 6.23.0의 구현이고, 타입은 이미 있는 `@types/node` 22.20.5의 전역 `WebSocket` 선언을 씁니다.

## 완료 기준

실제 연결은 저장소에 넣지 않는 확인 스크립트로 확인했습니다. 스크립트는 SDK를 소스 참조 조건(`@glasspod/source`)과 tsx로 불러오는 작은 앱을 띄우고, 실제 서버(`apps/server/src/index.ts`, 포트 18080)와 `ws`로 만든 가짜 서버(reject만 보냄, welcome을 보내지 않음, welcome 뒤 request와 JSON이 아닌 메시지를 보냄)에 붙여 봅니다.

| 확인 | 기대 결과 |
| --- | --- |
| `npm run typecheck` | exit 0 |
| `npm test` | 모든 테스트 통과. 재연결 간격 3개, 환경변수 읽기 7개 포함 |
| `npm run format:check` | `All matched files use Prettier code style!` |
| 서버 없이 시작 | `cannot connect to ...` 한 줄. 그 뒤 재시도에서는 경고 없음 |
| 서버를 켬 | 서버 로그 `hello accepted pod=shop/orders-1 ... sdk=node@0.0.0 protocol=1`, SDK 경고 `connected to ...` 한 줄 |
| 서버를 끔(SIGTERM) | SDK 경고 `connection lost (code 1001, server shutting down); reconnecting` 한 줄. 디버그 로그의 대기가 1·2·4·8초에 0~1초를 더한 값 |
| 서버를 다시 켬 | `connected to ...` 한 줄. 새 hello의 `instanceId`는 같고 `seq`는 이어짐(0 다음 1) |
| reject(가짜 서버) | `rejected by server: reason=unsupported-protocol; retrying` 한 줄, 재시도는 계속(8초에 3번) |
| welcome 없음(가짜 서버) | hello 뒤 10초에 끊고 `cannot connect to ... (no welcome within 10000ms)` 한 줄, 재연결 |
| 환경변수 빠짐, `http://` 주소 | `disabled: ...`, 앱은 계속 동작하고 exit 0 |
| `start()`를 두 번 부름 | 두 번째는 무시(디버그 로그 `start ignored: already started`) |
| welcome 뒤 request, JSON이 아닌 메시지 | 무시(디버그 로그) |
| `start({ app })` | hello에 `app`이 들어가고 `capabilities`는 없음 |
| `stop()` | 서버가 1000으로 닫힌 것을 봄. 재연결하지 않고 프로세스가 스스로 끝남 |
| 서버가 없을 때 앱이 할 일을 마침 | 프로세스가 스스로 끝남(타이머 unref) |
| 연결된 채 앱이 할 일을 마침 | 프로세스가 남음(내장 WebSocket 제약) |
| 위 모든 경우 | 처리되지 않은 예외 없음 |

직접 해 볼 때는 서버를 띄운 뒤 다른 터미널에서 실행합니다.

```bash
npm run dev:server
```

```bash
GLASSPOD_SERVER=ws://localhost:8080/agent POD_NAME=orders-1 POD_NAMESPACE=shop NODE_DEBUG=glasspod node --conditions=@glasspod/source --import tsx --input-type=module -e 'import { glasspod } from "@glasspod/sdk"; glasspod.start({ app: { name: "orders" } }); setInterval(() => {}, 60_000);'
```

서버 로그에 `hello accepted remote=::1 pod=shop/orders-1 ...`가 나오고, SDK 쪽에는 디버그 로그만 나옵니다. 서버를 껐다 켜면 SDK가 경고 두 줄(끊김, 복구)을 남기고 다시 붙습니다. 끝낼 때는 Ctrl+C로 멈춥니다.
