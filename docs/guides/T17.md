# T17 웹 뼈대

- 우선순위: P0 · 단계 2 · 선행 작업: T01
- 브랜치: `feat/t17-web-skeleton`
- 작성: 2026-11-14

## 목표

웹 화면(`apps/web`)의 뼈대를 만듭니다. 이후 작업(T18 Pod 목록, T19 Pod 상세, T21~T24 조치)이 화면만 더하면 되게 합니다.

- React + Vite 개발 서버(`npm run dev:web`)와 빌드(`npm run build:web`)
- 라우팅: 목록 `/`, 상세 `/pods/:namespace/:name`, 없는 주소
- 서버 HTTP API를 부르는 API 클라이언트. 실패는 서버의 오류 본문 `{ error, detail }`과 같은 모양으로 다룸
- Vite 프록시: 개발 서버가 `/api` 요청을 Glasspod 서버로 넘김
- 상세 자리에서 지금 있는 snapshot API(T09)를 불러 원본 JSON을 보여 줌. 데모 앱으로 끝까지 확인함

| 10 | 개발 서버 주소 | Vite 기본(`localhost:5173`). 다른 포트는 `npm run dev:web -- --port 5174` | 서버 HTTP API에 아직 인증이 없어(D4) 개발 서버를 노트북 밖에 열지 않음. Vite 기본이 localhost만 엶 |
| 11 | API 클라이언트의 결과 | 예외를 던지지 않고 `{ ok: true, status, data }` 또는 `{ ok: false, status, error, detail }`로 돌려줌. 서버의 오류 본문은 그대로 씀. 웹 화면이 붙이는 코드는 둘: `network-error`(서버나 개발 서버에 닿지 못함, `status` 0), `unexpected-body`(본문이 JSON이 아니거나 오류 본문이 `{ error, detail }` 모양이 아님) | 화면이 성공·실패를 같은 방식으로 그림. 서버(`{ error, detail }`, T09 결정 17)와 같은 모양 |
| 12 | 받은 데이터 검증 | 브라우저에서는 검증하지 않고 타입만 붙임. snapshot `data`는 서버가 이미 `validateSnapshotData`로 검증함 | 프로토콜 패키지의 검증 함수(Ajv)를 브라우저 번들에 넣지 않음 |
| 13 | HTTP API 본문 타입 | snapshot 성공·오류 본문 타입(`SnapshotBody`, `SnapshotErrorCode`, `SnapshotErrorBody`)을 서버에서 `@glasspod/protocol`의 `src/http.ts`로 옮기고, 공통 오류 본문 `ApiErrorBody`를 더함. 서버는 그것을 가져다 씀(동작은 같음). 손으로 쓴 TypeScript 타입이고 JSON Schema는 만들지 않음 | 서버와 웹이 함께 쓰는 타입은 `packages/protocol`에 둠(개발 지침). JSON Schema는 SDK–서버 메시지의 기준이고, HTTP API는 같은 저장소의 서버와 웹만 씀. 다른 조회 API와 형식 맞추기는 T14 |
| 14 | 소스 참조 | Vite의 `resolve.conditions`에 `@glasspod/source`를 더함. 지금은 `import type`만 써서 실행 코드에는 프로토콜 패키지가 들어가지 않음 | 라이브러리 패키지는 개발 때 빌드 없이 `src/`를 씀(T01) |

| 16 | 화면 | 공통 틀(로고, 글자 로고 `glasspod`, 'Pod 목록' 링크). 목록 자리 `/`는 안내 문장과 namespace·이름으로 상세를 여는 입력 칸. 상세 자리는 snapshot 원본 JSON과 '다시 불러오기' 버튼. 없는 주소는 '없는 화면' | 목록 API(T14)가 생기기 전에도 상세를 열 수 있게 함. 목록 화면은 T18, 상세 화면은 T19 |

| 18 | 글꼴과 다크 모드 | 글꼴은 `@theme`에 이름과 대체 글꼴만 적고(Pretendard, Manrope, JetBrains Mono → 시스템 글꼴) 글꼴 파일은 넣지 않음. 밝은 화면만 만듦 | 글꼴 파일을 어떻게 넣을지(직접 포함, CDN)는 화면을 꾸미는 T18에서 정함. 다크 모드 색은 D9(T18) |

## 범위

### 포함

- `apps/web`: Vite 설정(React, Tailwind, `/api` 프록시), `index.html`, 진입점, 라우트, 공통 틀, 목록·상세·없는 화면 자리, API 클라이언트와 훅, 단위 테스트
- `packages/protocol`: HTTP API 본문 타입(`src/http.ts`)
- `apps/server`: snapshot 본문 타입을 프로토콜 패키지에서 가져오게 고침(동작 변경 없음)
- 루트: `dev:web`, `build:web` 스크립트, devDependencies, `tsconfig.json` references

### 제외

- Pod 목록 API와 실시간 갱신(T14, D2), 목록 화면(T18), 상세 화면의 그래프·이벤트·snapshot 표시(T19, D8)
- 서버가 웹 화면 파일을 내주는 것과 클러스터에서의 접속(T20, D4). `vite preview` 설정
- 글꼴 파일, 다크 모드(T18, D9)
- 조치 버튼(T21~T24)
- ESLint(react-hooks 규칙 포함), 화면 테스트 도구

## 쓰는 법

서버, 데모 앱, 웹 개발 서버를 터미널 세 개에서 띄웁니다.

```bash
npm run dev:server
```

```bash
GLASSPOD_SERVER=ws://localhost:8080/agent POD_NAME=demo-1 POD_NAMESPACE=glasspod-demo npm run demo
```

```bash
npm run dev:web
```

브라우저에서 `http://localhost:5173/pods/glasspod-demo/demo-1`을 엽니다. 다른 주소의 서버를 쓰려면:

```bash
GLASSPOD_WEB_PROXY_TARGET=http://localhost:18080 npm run dev:web
```

상세 자리에서 보이는 것입니다.

| 경우 | 화면 |
| --- | --- |
| 데모 앱이 연결됨 | `HTTP 200`, 응답 시간, snapshot 원본 JSON(`state`에 `app.mode`) |
| 그 Pod의 SDK 연결이 없음 | `HTTP 404 · not-connected`와 `detail` |
| 앱이 막힘(`curl -s -X POST 'localhost:3001/faults/block?seconds=8'`) | 약 5초 뒤 `HTTP 504 · no-response` |
| 서버가 꺼짐 | `HTTP 502 · proxy-error`, `detail`에 서버 주소와 `ECONNREFUSED` |
| 웹 개발 서버도 꺼짐 | `network-error`(`status` 0) |

| `npm test` | 모든 테스트 통과. 응답 해석(성공, 서버 오류 본문, JSON이 아닌 본문, 빈 본문, 모양이 다른 오류 본문)과 경로 인코딩 테스트 포함 |
| `npm run format:check` | `All matched files use Prettier code style!` |
| `npm run build:web` | `apps/web/dist/`에 `index.html`과 JS·CSS가 생김. 번들에 Ajv가 없음 |
| `npm run dev:web` | `http://localhost:5173`에서 공통 틀과 목록 자리가 보임. 다른 컴퓨터 주소로는 열리지 않음 |
| 목록 자리의 입력 칸 | namespace와 이름을 넣으면 `/pods/:namespace/:name`으로 감 |
| 상세 자리, 데모 앱 연결됨 | `HTTP 200`과 snapshot 원본 JSON. '다시 불러오기'로 다시 부름(서버 로그 `request sent`) |
| 상세 자리, 연결 없는 Pod | `HTTP 404 · not-connected` |
| 상세 자리, 앱이 막힘 | 불러오는 중 표시 뒤 약 5초에 `HTTP 504 · no-response` |
| 상세 자리, 서버 꺼짐 | `HTTP 502 · proxy-error`와 서버 주소 |
| 상세 주소를 바로 열거나 새로 고침 | 같은 화면이 나옴(개발 서버가 `index.html`을 줌) |
| 없는 주소(`/nope`) | '없는 화면'과 목록으로 가는 링크 |
| 잘못된 프록시 대상(`GLASSPOD_WEB_PROXY_TARGET=abc`, `ftp://x`, `http://localhost:8080/api`) | 개발 서버가 시작하지 않고 원인을 알림 |
| 브라우저 콘솔 | 앱의 오류 없음. 2xx가 아닌 응답(404, 504 등)은 브라우저가 스스로 `Failed to load resource`로 남김 |
