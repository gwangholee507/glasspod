- 우선순위: P0 · 단계 11 · 선행 작업: T19, T22, T23, T34 · 결정: 없음(아래 결정 1~4는 착수 전 사용자 결정)

## 목표

design.md 6장 '대표 시나리오: Pod 하나가 느려질 때'의 1~5단계를 로컬 클러스터에서 처음부터 끝까지 따라가며, 1차 범위(MVP)로 만든 기능이 함께 맞물려 동작하는지 확인합니다.

1. Pod A의 큐 길이가 계속 늘어나고 SDK가 이 값을 서버로 보냅니다. 헬스체크는 통과하므로 쿠버네티스는 아무 일도 하지 않습니다.
2. 서버가 Pod A의 값이 다른 Pod보다 높은 것을 보고 목록의 '지금 볼 것'에 넣습니다(7.6).
3. 개발자가 Pod A 상세를 열어 마지막 예외가 DB timeout인 것을 확인합니다.
4. '트래픽에서 빼기'를 누르면 새 Pod가 트래픽을 받고 Pod A는 그대로 남습니다.
5. Pod A를 계속 보다가 '격리된 Pod'에서 삭제합니다.

6단계(규칙 등록)는 자동 규칙(T28)이고 문법(D5)은 이 점검이 끝난 뒤 정합니다.

결정 3의 작은 문제입니다. 서버·SDK는 바꾸지 않았습니다.

- 상세 네 번째 그래프의 기본값이 5xx였음(서버의 `outliers` 순서가 요청 p99 → 5xx → 예외 → `app.*`이고 그 가운데 그릴 수 있는 첫 것) → 높은 값 가운데 `app.*` gauge를 먼저 고름(`detailView.ts`의 `chooseFourthChart`). 대표 시나리오의 신호가 큐 길이이고 T19의 원래 기본값도 `app.*` gauge가 먼저. 고친 뒤 기본값 `app.queue.length`
- 새 Pod가 처음 정상이 된 판단 변화('시작 중 → 정상', 'SDK 없음 → 정상')가 '다시 정상입니다'로 나옴 → '이상 신호가 없습니다'(`podText.ts`의 `changeSentence`). 앞 판단이 그 밖의 것(앱 멈춤 의심, 재시작 등)이면 그대로 '다시 정상입니다'
- 삭제·재시작·스케일 서랍의 '지운 Pod의 기록은 이 화면에 30분 남습니다'가 격리된 Pod 화면(지우면 바로 빠짐)과 한눈에 보기 카드(결정 4로 빠짐)에서 맞지 않음 → "지운 Pod는 Pod 목록의 '종료됨'에 30분 남아 기록을 볼 수 있습니다."(`RestartDrawer.tsx`, `DeleteDrawer.tsx`, `actionText.ts`의 `scalePlan`)

### 넘길 것(고치지 않음)

설계를 바꿔야 하거나 정해진 동작이라 결정 3대로 고치지 않았습니다.

- 격리된 Pod 카드의 '격리할 때 판단'은 판단(7.5)만 남아, 지표 비교 강조로 뺀 Pod도 '정상'으로 보임. 왜 뺐는지(그때의 `outliers`)를 남기려면 서버가 격리 주석에 더 적어야 함(T23 주석 형식 변경)
- 지표 비교 강조는 판단 변화가 아니라 한눈에 보기 타임라인과 상세 '무슨 일이 있었나'에 남지 않음(T34 결정 14). 강조가 꺼지거나 Pod를 격리한 뒤에는 2단계가 화면 기록에 없음. 자동 규칙(T28)의 '알림만'과 함께 정할 일
- 처음부터 배포하면 부하가 데모 앱보다 먼저 시작해 첫 10초에 `failed`가 몇 건 남(이번 6건). 데모 전용이고 시나리오와 상관없음
- 데모 앱이 서버보다 먼저 뜨면 SDK 첫 연결이 실패한 뒤 다시 붙고, 그 몇 초 동안 판단이 'SDK 없음'(타임라인에 남음). 정해진 동작(T04 재연결, T13 판단)

## 쓰는 법

대표 시나리오를 다시 해 볼 때의 순서입니다. 쿠버네티스 명령 전에 context를 확인합니다(`docker-desktop`이어야 함).

```bash
kubectl config current-context
```

서버 API와 화면을 엽니다(README '로컬 클러스터에서 띄워 보기').

```bash
kubectl -n glasspod port-forward service/glasspod-server 8080:8080
```

```bash
npm run dev:web
```

`http://localhost:5173/?namespace=glasspod-demo`를 열고, 데모 앱 Pod 하나(Pod A)를 골라 관리 포트를 엽니다.

```bash
kubectl -n glasspod-demo port-forward pod/<Pod A> 3001:3001
```

```bash
curl -s -X POST 'localhost:3001/faults/slow?delayMs=1500'
```

- 약 30초 안에 Pod A가 '지금 볼 것'에 들어갑니다. 상세에서 '트래픽에서 빼기'를 누르고, 왼쪽 메뉴 '격리된 Pod'에서 삭제합니다.
- Pod A를 지우면 고장도 함께 사라집니다. 삭제하지 않고 끝낼 때는 `curl -s -X DELETE localhost:3001/faults`로 끕니다.
