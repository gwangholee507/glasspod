# T34 지표 비교로 이상한 Pod 강조

- 우선순위: P0 · 단계 8 · 선행 작업: T13 · 결정: 없음(아래 결정 1~4는 착수 전 사용자 결정)
- 브랜치: `feat/t34-metric-outliers`
- 작성: 2026-11-25

## 목표

같은 Deployment의 다른 Pod보다 지표가 눈에 띄게 높은 Pod를 서버가 찾아 화면에 강조합니다(design.md 6장 대표 시나리오 2단계 '서버는 Pod A의 값이 다른 Pod보다 높은 것을 보고 화면에 강조합니다'). 쿠버네티스 헬스체크는 통과하는데 한 Pod만 느리거나 큐가 쌓이는 경우를 개발자가 목록에서 바로 보게 합니다.

- 서버: 판단 주기(1초)마다 같은 namespace·Deployment의 Pod끼리 지표를 비교하고, 15초 이어진 것만 `PodItem.outliers`로 내보냅니다. 판단(7.5 표, `PodStatus`)은 바꾸지 않습니다.
- 웹: 높은 지표가 있는 Pod를 '지금 볼 것'에 주의로 넣고, 목록 지표 칸을 주의 색으로 칠하고, 목록 항목과 상세 머리줄에 '다른 Pod보다 높음' 한 줄을 보입니다.
- 오래된 지표 값(3주기보다 오래됨)은 비교에서 빼고 목록에도 '—'로 둡니다(T23에서 넘긴 '요청 p99 마지막 값').

## 결정 사항

1~4는 2026-11-25에 사용자가 정했습니다(착수 전에 보고한 질문 4개, 모두 추천안). 5~20은 이 작업의 기본값입니다.

## 구현하며 확인한 것

Node 22.22.0, 내장 브라우저(Chromium), 로컬 클러스터(클러스터 안 서버 `glasspod-server:dev`, 데모 앱 3개와 `demo-load` 초당 10건)에서 2026-11-25에 확인했습니다. 8080과 5173은 앞 작업에서 띄운 노트북 서버와 Vite가 쓰고 있어, T24처럼 클러스터 안 서버를 18080으로 port-forward하고 Vite를 5175로 따로 띄웠습니다. 관리 포트는 Pod마다 13001~13003으로 port-forward했습니다.

확인 중 고친 것:

- 판단이 정상인 Pod에 '이상 신호 없음'과 '다른 Pod보다 높음'이 함께 나와 앞뒤가 어긋남 → 정상 판단의 문장을 '연결과 쿠버네티스 상태는 정상'으로(결정 15)

- 격리된 Pod 화면의 안내 '새 요청이 없으면 요청 p99는 마지막으로 받은 값에 머뭅니다'(T23)가 결정 4와 맞지 않음 → '지표 3주기(기본 15초) 뒤 '—'로 바뀝니다'

## 범위

### 포함

- `packages/protocol/src/http.ts`: `PodOutlier`, `PodItem.outliers`, `PodListMetrics` 설명(오래된 값)
- `apps/server`: 비교와 켜고 끄기, 예외/분, 목록 지표의 오래된 값, 판단 주기 연결, 로그, 단위 테스트
- `apps/web`: 목록 항목(지금 볼 것, 칸 색, 한 줄), 상세 머리줄, 네 번째 그래프 기본값, 단위 테스트

### 제외

- 판단 표(7.5)와 판단 변화 기록 바꾸기(결정 3, 14)
- 낮은 값 강조, 앱마다 기준 바꾸기, 알림(자동 규칙 T28)
- 한눈에 보기 Deployment 요약 바꾸기(결정 18), 상세 그래프에 기준선 그리기

```text
├─ pages/IsolatedPage.tsx                     # (고침) 요청 p99 안내 문장(결정 4)
└─ api/usePodDetail.ts                        # (고침) 네 번째 그래프에 높은 지표
```

## 알려진 한계

- 기준(2배, 최소 차이, 15초)은 고정입니다. 앱마다 정상 값이 다르면 맞지 않을 수 있습니다(바꾸는 것은 자동 규칙 T28).
- Pod가 2개면 어느 쪽이 이상한지 '높은 쪽'으로만 정합니다. Pod 1개(또는 비교할 다른 Pod가 없음)면 비교하지 않습니다.
- 예외/분과 5xx/분은 서버가 받은 시각 기준입니다. SDK가 끊겼다가 보관한 event를 한꺼번에 보내면 그 뒤 1분 동안 예외/분이 높게 보일 수 있습니다.
- 5xx/분과 예외/분은 최근 60초 합이라 고장이 끝나도 1분 가까이 높게 남고, 0이 된 뒤 15초가 지나야 강조가 꺼집니다. 꺼지기 전 15초 동안은 지금 값(예: '5xx 0/분 (다른 Pod 0/분)')을 보입니다.
- 강조는 서버 메모리에만 있어 서버를 다시 시작하면 15초 뒤에 다시 켜집니다. 기록(타임라인)에는 남지 않습니다.
