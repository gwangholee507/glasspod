# T21 조치 공통

- 우선순위: P0 · 단계 9 · 선행 작업: T16 · 결정: 없음(아래 결정 1~3은 착수 전 사용자 결정)
- 브랜치: `feat/t21-actions`
- 작성: 2026-11-21

## 목표

개발자가 화면에서 버튼을 눌러 쿠버네티스 조치를 실행하는 공통 길을 만듭니다(design.md 5.3 '조치 버튼', 5.4). 조치마다 다른 것은 쿠버네티스 호출과 서랍의 내용뿐이고, 나머지는 모든 조치가 같은 길을 지납니다.

- 서버: 조치 API(`POST /api/actions`), namespace 제한, 대상 확인(uid), 같은 대상 중복 막기, 쿠버네티스 호출 시간 제한, 조치 기록(저장소, 조회 API, SSE)
- 웹: 오른쪽 확인 서랍(Figma 확정-3), 조치 기록 화면(확정-5, `/actions`), 상세의 조치 기록 칸과 '무슨 일이 있었나' 줄, 한눈에 보기 타임라인의 조치 줄
- 첫 조치: Pod 재시작(Pod 삭제). 공통 길을 클러스터에서 처음부터 끝까지 확인합니다(결정 1).

## 결정 사항

1~3은 2026-11-21에 사용자가 정했습니다(착수 전에 보고한 질문 3개, 모두 추천안). 4~24는 이 작업의 기본값입니다.

## 결과 문장

성공 문장은 조치마다, 실패 문장은 오류 코드마다 정합니다. 쿠버네티스가 답한 상태 코드(`kubeStatus`)가 있으면 앞에 `HTTP 404 · `처럼 붙입니다.

| 경우 | 문장 |
| --- | --- |
| 재시작 성공 | Pod를 지웠습니다. ReplicaSet `X`이 새 Pod를 만듭니다. (ReplicaSet이 없으면 'Pod를 지웠습니다.') |
| `action-not-allowed` | 이 namespace는 조치가 꺼져 있습니다(GLASSPOD_ACTION_NAMESPACES). |
| `kube-unavailable` | 서버가 쿠버네티스에 연결되어 있지 않습니다. |
| `target-not-found` | Pod가 이미 지워져 있습니다. |
| `target-changed` | 같은 이름의 다른 Pod로 바뀌었습니다. 목록을 다시 보고 실행합니다. |
| `target-terminating` | Pod가 이미 지워지는 중입니다. |
| `action-in-progress` | 이 대상에 실행 중인 조치가 있습니다. |
| `kube-forbidden` | 서버에 이 조치 권한이 없습니다(RBAC Role). |
| `kube-error` | 쿠버네티스가 조치를 거부했습니다. |
| `kube-timeout` | 쿠버네티스가 10초 안에 답하지 않았습니다. 실행됐는지 목록에서 확인합니다. |
| 서버에 닿지 못함·그 밖 | 조치를 보내지 못했습니다(`코드`). |

## 범위

### 포함

- `packages/protocol/src/http.ts`: 조치 타입(`ActionKind`, `ActionItem`, `ActionRequest`, `ActionBody`, `ActionsBody`, 오류 코드), `PodListBody.actionNamespaces`, `PodListChanges.actions`, `PodDetailBody.actions`
- `apps/server`: 설정, 조치 API, 재시작 실행, 조치 기록(저장소, 조회, SSE), 로그, 단위 테스트
- `apps/web`: 서랍, 재시작 버튼, 조치 기록 화면과 메뉴 링크, 상세 칸, 타임라인 줄, 단위 테스트
- `deploy/server/`: Role에 `pods: delete`, `GLASSPOD_ACTION_NAMESPACES`

### 제외

- 트래픽에서 빼기와 격리된 Pod 화면(T23), 스케일 조정과 HPA 경고(T24), 전체 재시작·롤백(T29)
- preStop 지연과 재시작 때 부하 실패(T22, T15에서 넘김)
- 서버 미리 보기 API(결정 17), 로그인과 실행한 사람 이름(결정 4), 조치 기록을 DB에 남기기(T32)

## 알려진 한계

- 실행 주체는 모두 '개발자'입니다. 누가 눌렀는지는 남지 않습니다(로그인 없음, 결정 4).
- 메모리 저장소라 서버를 다시 시작하면 조치 기록이 사라집니다(결정 3, DB는 T32).
- `kube-timeout`이면 쿠버네티스가 실행했는지 서버도 모릅니다(결정 8).
- 영향 미리 보기는 화면이 받은 목록으로 계산하므로 Deployment가 없는 Pod(직접 만든 Pod)는 다른 Pod를 보여 주지 않습니다.

## 쓰는 법

```bash
GLASSPOD_KUBE_CONTEXT=docker-desktop GLASSPOD_ACTION_NAMESPACES=glasspod-demo npm run dev:server
```

```bash
curl -s -X POST localhost:8080/api/actions -H 'Content-Type: application/json' -d '{"action":"restart-pod","target":{"namespace":"glasspod-demo","name":"<Pod>"},"expectedUid":"<uid>"}'
```

```bash
curl -s 'localhost:8080/api/actions?namespace=glasspod-demo'
```

uid는 `curl -s 'localhost:8080/api/pods?namespace=glasspod-demo'`의 `pods[].kube.uid`에 있습니다. 클러스터 안 서버는 `deploy/server/server.yaml`에 값이 들어 있습니다.
